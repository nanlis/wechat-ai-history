# 架构：三层结构与设计取舍

> 一句话：**把微信 4.x 的本地聊天记录，变成 AI 可以直接调用的能力。**

不是「导出聊天记录」（那是结果），不是「破解微信」（那是手段）。
真正做的是一件事：**在用户自己的电脑上，给 AI 装上一双能读微信的眼睛。**

---

## 一、为什么这件事不能用「装个软件」解决

微信 4.x 的现状：

- **WeChat 官方**没有导出接口。备份是加密的、换机就废。
- **微信 4.0+** 把 OpenSSL **全静态链接**进 DLL —— 扫了 8773 个导出符号，
  **没有一个** PBKDF2 / HMAC / sqlite3_key 能钩。常规「内存扫密钥」全部失效。
- **wx-cli** 只认 `~/Documents/xwechat_files`，认不出用户自定义的数据路径，
  `init` 直接卡死 → 提不出密钥。
- **WeFlow**（11k stars）：做得很全，但 README 明说
  > 「依赖**自定义的原生解密组件，需自行设计**」

**最后这一条是关键。** 也就是说：现成的工具都到不了最后一公里。
本仓库填的正是被外包出去的那一公里。

## 二、三层结构（知识层 / 能力层 / 内核层）

```
AI 客户端                WorkBuddy · Claude Code · Codex
    ↓
Skill                    wechat-local-history —— 教 AI 何时调、怎么调、有哪些坑
    ↓
MCP Server               wechat-local —— 7 个工具，stdio，本地
    ↓
内核                     本仓库 —— 提密 → 解密 → 查询
    ↓
数据                     微信本地数据目录（SQLCipher 4 加密）
```

三层缺一不可：

| 只做这层 | 后果 |
|---|---|
| 只有 Skill | AI 知道有这回事，但每次要现拼 bash 命令 |
| 只有 MCP | AI 根本不知道这个工具存在，不会主动用 |
| 只有内核 | 每次都要手动敲参数，不是「能力」，是「脚本」 |

**Skill 和 MCP 不是二选一，是上下游。**

## 三、每层具体交付了什么

### 内核层

| 突破 | 难度 | 说明 |
|---|---|---|
| **密钥提取** | ★★★★★ | 微信把 OpenSSL 全静态链接，常规手段全废。最终靠**钩 SHA-512 压缩函数**，从 HMAC 内层的 ipad 块（key ⊕ 0x36）XOR 回明文 |
| **大库流式解密** | ★★★ | 整文件读进内存 → MemoryError。改逐页处理，16 万级页 **8 秒**跑完 |
| **跨分片搜索** | ★★ | 多个消息分片库合并检索，百万条消息秒级响应 |
| **账号无关化** | ★★★ | 密钥自己认账号，不靠目录时间戳猜「哪个是活跃账号」 |

三个决定成败的细节（换微信版本会踩的坑）：

1. **只钩 `Weixin.dll` 会抓到 TLS 的 HMAC 假货** —— 必须扫全部模块
2. **候选必须落盘再离线验证** —— 在线验证会漏，TLS 假货就是这么混进来的
3. **微信登录那一刻**是唯一可靠触发点 —— SQLCipher 只在首次开库时派生密钥

### 能力层（MCP Server）

7 个工具，端到端验证通过（标准 MCP 客户端握手 + 实调）：

```
wechat_list_chats       列会话 / 找群 id
wechat_read_chat        读某个群或好友
wechat_search_messages  全文搜索
wechat_recent_messages  最近消息
wechat_chat_summary     摘要
wechat_system_events    撤回 / 转账 / 群变更等系统事件
wechat_list_accounts    列出本机可用账号（多账号场景）
```

MCP 是标准协议，任何支持它的 AI 客户端（WorkBuddy / Claude Code / Codex）都能直接用同一份。

### 知识层（Skill）

一份声明式的 `SKILL.md`，装到各 AI 运行时。里面写的全是**实测踩出来的坑**，不是抄文档：

- 群名要先 list 换 wxid 再 read
- `days` 是时间窗不是条数，用户说「这个群的记录」通常指全部历史
- 搜不到要扩 days 到 120/365 再回答「没有」
- 富媒体正文是 WCDB 单独加密的，**拿不到就说拿不到，不许编造**
- `tasklist` 在沙箱下返回 0 行，改用 frida 枚举

### 运维层（refresh_key.sh）

微信一重启就得重跑一遍流程。现在一条命令：

```bash
bash scripts/windows/refresh_key.sh
```

自动完成：查进程 → 挂钩 → 等登录 → 提密 → 流式解密 → 验证会话数。

## 四、明确**没有**做什么（以及为什么）

| 没做 | 原因 |
|---|---|
| **独立 GUI 软件** | WeFlow 已覆盖浏览 / 年度报告 / 导出，且 11k stars。重复造轮子 |
| **朋友圈解密** | 与聊天记录是另一套加密，范围另算 |
| **富媒体正文解码** | WCDB 单独加密，仓库有 `export_media.py` / `voice_decode.py` 可接，需要额外密钥 / 模型 |
| **任何云端 / 上传** | 隐私底线：密钥等同账号钥匙，聊天涉及他人隐私。**全程本机，零联网** |

## 五、这套方案对使用者的价值

**交互层面**：以前「把群里的记录发给我」要走：截图 → 复制 → 粘贴 → 格式全乱 → 上下文丢一半。
现在：**一句话**，而且 AI 拿到的是**结构化的、带时间戳和发送者的原文**，百万条随便搜。

**可复用性**：WeFlow 作者说「解密组件需自行设计」。本仓库的内核**可以是那个组件**——
不止一个人能用，WeFlow 用户也能用。做成可分发的包，是把「自己能用」变成「别人也能用」。

## 附：安全边界（不可妥协）

- 密钥（`key_windows.txt`）= 微信账号的钥匙，**绝不外传、不入 git、不打印到对话**
- 明文库涉及群友隐私，**只在本地，永不外传**
- 只操作用户本机、用户有权访问的数据
- Skill 里已写死 `Never print a raw key`
