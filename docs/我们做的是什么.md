# 我们做的是什么

> 一句话：**把微信 4.x 的本地聊天记录，变成了 AI 可以直接调用的能力。**

不是"导出聊天记录"（那是结果），不是"破解微信"（那是手段）。
真正做的是一件事：**在你的电脑上，给 AI 装上一双能读微信的眼睛。**

---

## 一、为什么这件事不能用"装个软件"解决

2026-10-25 的现状：

- **WeChat 官方**没有导出接口。备份是加密的、换机就废。
- **微信 4.0+** 把 OpenSSL **全静态链接**进 DLL —— 扫了 8773 个导出符号，
  **没有一个** PBKDF2 / HMAC / sqlite3_key 能钩。常规"内存扫密钥"全部失效。
- **本机原有的 `wx-cli`**：只认 `~/Documents/xwechat_files`，认不出你的 D 盘自定义路径，
  `init` 直接卡死 → 提不出密钥。
- **本机原有的 `wechat-local-data` 技能**：指向的正是这个失效的 wx-cli。
- **WeFlow**（11k stars）：做得很全，但 README 明说
  > 「依赖**自定义的原生解密组件，需自行设计**」

**最后这一条是关键。** 也就是说：现成的工具都到不了最后一公里。
今天做的，正是被外包出去的那一公里。

## 二、三层结构（知识层 / 能力层 / 内核层）

```
AI 客户端                WorkBuddy · Claude Code · Codex
    ↓
Skill                    wechat-local-history —— 教 AI 何时调、怎么调、有哪些坑
    ↓
MCP Server               wechat-local —— 6 个工具，stdio，本地
    ↓
内核                     wxdec-skill —— 提密 → 解密 → 查询
    ↓
数据                     D:\WeChatData\xwechat_files —— 1.3GB / 115 万条 / 7521 会话
```

三层缺一不可：

| 只做这层 | 后果 |
|---|---|
| 只有 Skill | AI 知道有这回事，但每次要现拼 bash 命令 |
| 只有 MCP | AI 根本不知道这个工具存在，不会主动用 |
| 只有内核 | 每次都要手动敲参数，不是"能力"，是"脚本" |

**Skill 和 MCP 不是二选一，是上下游。**

## 三、每层具体交付了什么

### 内核层（今晚真正的技术战果）

| 突破 | 难度 | 说明 |
|---|---|---|
| **密钥提取** | ★★★★★ | 微信把 OpenSSL 全静态链接，常规手段全废。最终靠**钩 SHA-512 压缩函数**，从 HMAC 内层的 ipad 块（key ⊕ 0x36）XOR 回明文 |
| **676MB 流式解密** | ★★★ | 官方 `decrypt_all.py` 整文件读进内存 → MemoryError。改逐页处理，165,284 页 **8 秒**跑完 |
| **跨分片搜索** | ★★ | `message_0.db` + `message_1.db` 两片合并检索，搜"某联系人"命中 2898 条 |

三个决定成败的细节（换微信版本会踩的坑）：

1. **只钩 `Weixin.dll` 会抓到 TLS 的 HMAC 假货** —— 必须扫全部 10 个模块
2. **候选必须落盘再离线验证** —— 在线验证会漏，4 个 TLS 假货就是这么混进来的
3. **微信登录那一刻**是唯一可靠触发点 —— SQLCipher 只在首次开库时派生密钥

### 能力层（MCP Server）

6 个工具，端到端验证通过（官方 MCP 客户端握手 + 实调）：

```
wechat_list_chats       列会话/找群 id
wechat_read_chat        读某个群或好友
wechat_search_messages  全文搜索
wechat_recent_messages  最近消息
wechat_chat_summary     摘要
wechat_system_events    撤回/转账/群变更等系统事件
```

已注册到 `C:\Users\<user>\.workbuddy\mcp.json`。
**别的 AI 客户端（Claude Code / Codex）也能直接用同一份**——这是 MCP 的好处。

### 知识层（Skill）

`~/.skills-manager/skills/wechat-local-history/SKILL.md`，已软链到 7 个运行时。

里面写的全是**实测踩出来的坑**，不是抄文档：

- 群名要先 list 换 wxid 再 read
- `days` 是时间窗不是条数，用户说"这个群的记录"通常指全部历史
- 搜不到要扩 days 到 120/365 再回答"没有"
- 富媒体正文是 WCDB 单独加密的，**拿不到就说拿不到，不许编造**
- `tasklist` 在沙箱下返回 0 行，改用 frida 枚举

### 运维层（refresh_key.sh）

之前微信一重启就得手工重跑一遍流程。现在一条命令：

```bash
bash /d/Projects/wxdec-skill/scripts/windows/refresh_key.sh
```

自动完成：查进程 → 挂钩 → 等登录 → 提密 → 流式解密 → 验证会话数。

## 四、我们**没有**做什么（以及为什么）

| 没做 | 原因 |
|---|---|
| **独立 GUI 软件** | WeFlow 已覆盖浏览/年度报告/导出，且 11k stars。重复造轮子，还挡着别人的路 |
| **朋友圈解密** | 今晚的任务是聊天记录；朋友圈是另一套加密 |
| **富媒体正文解码** | WCDB 单独加密，仓库有 `export_media.py`/`voice_decode.py` 可接，需要额外密钥/模型 |
| **任何云端/上传** | 隐私底线：密钥等同账号钥匙，群友聊天涉及他人隐私。**全程本机，零联网** |

## 五、现在它值什么

**从你的视角**：
以前"把群里的记录发给我"要走：截图 → 复制 → 粘贴 → 格式全乱 → 上下文丢一半。
现在：**一句话**，而且 AI 拿到的是**结构化的、带时间戳和发送者的原文**，115 万条随便搜。

**从圈子的视角**：
WeFlow 作者说"解密组件需自行设计"。我们这个内核**可以是那个组件**——
不止你能用，WeFlow 用户也能用。做成可分发的包，是把一个"自己能用"变成"别人也能用"。

**对你的内容线**：
179 个群里躺着 115 万条真实讨论。"<群名占位>"就有 5.5 万条实操干货。
这些是**别人已经验证过的真实经验**，比任何教程都值钱——
可以做选题挖掘、做方法论验证、做"AI 工作流实战"的素材库。

## 附：安全边界（不可妥协）

- 密钥（`key_windows.txt`）= 微信账号的钥匙，**绝不外传、不入 git、不打印到对话**
- 明文库涉及群友隐私，**只在本地，永不外传**
- 只操作用户本机、用户有权访问的数据
- Skill 里已写死 `Never print a raw key`
